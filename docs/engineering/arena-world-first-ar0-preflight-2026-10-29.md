## Current executable data ownership — crosswalk

| Link | Source-backed present state | AR0 mismatch / preservation rule |

| Chart world/route generation | `src/Wyrmforge.Application/Runs/Navigation/WyrmrealmMapGenerator.cs` produces C# region-specific `WyrmrealmTerritory`, `HuntRoad` roads, camp, river, bridge and terrain features, with Tier I–III authored forks, refuge/watchtower, graph predecessor edges and stable node names. `WyrmrealmRouteGenerator.cs` associates encounter/reward profiles. | Keep the existing connected route choices, deterministic Tier I–III progression, rarity and rewards. The chart map is not a decoder for an external illustration. |
| Chart identity and projection | `WyrmrealmMapNode.cs` has `Id`, `Graph.PreviousNodeIds`, `Site`, `Territory`, `Habitat`, `PreLair`, `Refuge`, `Watchtower`. `WyrmrealmTerritory.cs` has `HuntSite(Point, RoadId, RoadIndex, BonusRelic, IncomingTrail)` and `HuntRoad(Id, ..., Points, ...)`. `Features/Map/WyrmrealmMapView.razor` draws a chart from those exact C# roads, features and node connections. | No **explicit shared versioned local site-space recipe** with graph-edge → entrance/exit **port IDs and directions**, local landmarks/obstructions, semantic material IDs, height/slope/moisture/wear or discovery fields. Existing `Id`/`Site`/`Territory` should be extended/mapped, not discarded for a second world model. |
| Selection → simulation | `src/Wyrmforge.Application/Runs/Simulation/Navigation/RunSimulation.Navigation.cs` `ChooseMapNode(id)` delegates to `mapState.Choose`, then calls `ArenaEnvironmentState.Create(mapState.Seed, node)`. `WyrmrealmMapState.cs` owns available/completed nodes and route commitment. | The bridge from chart topology to local physical arena is currently **seed/node metadata**, not a mapped edge-to-local-exit geometry contract. Preserve node choice, transition, score and reward behavior. |
| Arena layout and collision | `Environment/ArenaEnvironmentState.cs` creates local seed from map seed, stage, lane (and road index only for generator preview), builds encounter phase barriers, supplies and physical props, and owns movement restriction, LOS, spawn repair, collisions and collection. `Environment/HuntArenaGenerator.cs` supplies props and separate `GenerateWetForest(seed)` (`WetForestRecipe` with trail and ground ellipses). | Local C# arena geometry is not derived from the chart's `HuntSite.IncomingTrail` or required outgoing graph edges; two different chart connections cannot reliably become their corresponding local ports. Protect real C# physical authority and existing fallback gates. Reuse and adapt these components; do not add JS-authoritative path/collision. |
| Snapshot → render | `Simulation/Snapshots/ArenaEnvironmentRenderSnapshot.cs` exposes seed/biome/element/stage/landmark/supplies/barriers/district/habitat, plus `WetForest` and props; **no chart node/site/region IDs, version, edge/port layout or semantic material samples**. `ArenaEnvironmentState.Snapshot()` creates it. | AR0 needs one versioned C# site/arena recipe projected both to Chart and actual in-Hunt render snapshot, with typed surface identifiers and geographic diagnostics. Do not use color strings as gameplay state. |
| Visual path / fallback | `wwwroot/js/arena-environment.js` builds a seeded `createTerrainPlan`; `arena-territory-art.js` independently builds biome/district `createTerritoryStoryPlan`, palettes and decorative patches from environment seed. `wwwroot/js/arena.js` is the live Hunt compositor; `Features/Arena/ArenaView.razor` hosts the live canvas. | These JS plans are **presentation-only**, not a valid geographic source. Flat-color semantic debug output must use the same live camera/render adapter as production. Preserve live default until approved, use shared G renderer at actual cutover, and retire redundant presentation recipes only after parity. |
| Exit semantics | `Environment/RunSimulation.TrailExit.cs` currently places one fixed physical exit at `(arenaWidth * .5, max(80, arenaHeight * .11))`, revealed after trail completion. `RunSimulation.Navigation.cs` owns completion, one-time `rewardedRouteNodeIds`, refuge and scouting hooks. | This exit is not associated with named chart edges or correct fork directions. AR0 must explicitly distinguish current *single-trail progression* from future site ports, never silently change route commitment, boss pacing or duplicate-reward behavior. |
| Existing tests | `tests/Wyrmforge.Application.Tests/Runs/Navigation/FireTierTwoHuntTests.cs`, `FireTierThreeHuntTests.cs`, `Runs/Simulation/ArenaEnvironmentStateTests.cs` and `ArenaCrossingTests.cs` protect current route/collision behavior.
