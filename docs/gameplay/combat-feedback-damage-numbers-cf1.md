# CF1 — WyrmForge combat-number visual language

**Owner direction:** individual hits are satisfying; damage over time feels like a different physical phenomenon. The game remains dark Gothic, not a bright arcade scoreboard. This document describes the implemented renderer and the staged future adapters. The actual C# damage simulation always owns health, deaths and school/status identity.

## Non-negotiable invariants

- The only event source is C# post-defense HP loss. No JS random damage, speculative critical hits, status procs, or additional combat engines.
- Preserve the four-argument `RunSimulation.DamageTarget` and `Splash` signatures used by legacy reflection-based tests. The internal `DamageTargetWithFeedback` and `SplashWithFeedback` paths attach source traits.
- A confirmed C# damage event has a stable sequence, position, true amount, school, whether it is periodic, its C#-classified flavor, and grounded empowered/heavy/finisher flags.
- Finishing blows use weight and warmth; **never append exclamation marks**. Genuine criticals, if later implemented in C#, must gain a separate source-authored semantic signal rather than using the heavy flag as a fake crit.
- Presentation annotations are not lights, visual-physics particles, actor animations, nor new damage/status effects.

## Damage-family art direction

| Family | Production visual | Actual source |
| --- | --- | --- |
| Direct Fire/Frost/Storm/Arcane | School-tinted 900-weight crisp text, fast elastic launch, controlled rise | Spell/projectile/chain actual damage |
| Heavy hit | Slightly larger number, warmer accent, sharper launch. `Heavy` is true when one real non-periodic hit removes at least max(8 HP, 16% max target HP) | C# real HP delta |
| Focus/surge hit | Larger, gold-leaning emphasis, no false crit marker | C# `Surge` |
| Finisher | Larger warm-ivory impact, persistent enough to read after death. No “!” or comic punctuation | C# kill |
| Burn tick | Smaller orange ember, damped spring, lateral heat flicker, pair of 1–2 px ember flecks | Existing Burning status DPS |
| Scorched-ground tick | Lower brick orange, mild horizontal simmer, smaller vertical lift | Existing Fireball burning-ground DPS |
| Frost tick | Icy micro-shiver, restrained drift, short crystal-like flecks | **Ready for future C# frost damage**, not generated for current non-damaging Chill/Frozen |
| Storm tick | Sharp snap and asymmetric lateral jitter | **Ready for future C# electrical DoT**, not generated for current non-damaging Shocked |
| Necrotic tick | Soft olive/ashen tone, downward settling pulse | **Ready for future real necrotic DoT**, not generated by existing non-damaging debuffs |
| Other periodic | Small spring and quick fade, neutral inky tint | Future explicitly classified source |

## Timing and readability

- Floating text lifetime: 0.8 simulated seconds. The run pause freezes lifetime; resetting an encounter clears stale text.
- Rapid direct hits on the same target and school aggregate within 0.12 s; periodic damage of the same source family aggregates within 0.30 s. Burn and Scorch do not merge into each other.
- Maximum 48 active number records. World-viewport culling on the renderer, five deterministic horizontal lanes, and base position above actor shoulders rather than over the target's foot-centered sigil.
- Reduced motion removes drift, bounce, jitter, and accent particles, but preserves readable static text and fade.
- Full shows all numbers; Minimal hides DoT/tick noise and reduces nonperiodic type size; Off does not paint any text. Mode lives in browser preferences, not saved build/character progression.
- Two tiny screen-ink flecks are the maximum accent for a periodic number. No `Math.random`, DOM node per number, GPU emitter, bloom, or per-enemy renderer. CSS is limited to the settings control.

## Gate checklist

1. Existing `DamageTarget`/`Splash` reflection consumers remain compatible. Source-authorized HP delta matches snapshot value after shields, defense, phase gates and overkill caps.
2. Burning vs ground scorch differs at a glance. Shocked and Chilled without HP loss render no fake tick.
3. All six school direct-hit palettes remain distinct. The default/unknown source is readable neutral ink, never reclassified as a different school.
4. JS presentation tests cover ticks, future adapter families, reduced motion, Off/Minimal/Full, stable lanes, and renderer ordering above the universal Gothic night.
5. Run `Validate Wyrmforge`, browser shards, mobile 390px in-Hunt screenshot/GIF and real iPhone readability/thermal checks. A CI pass alone is not visual acceptance.
6. The separately running animation, AI, Hollowed rebuild and GPU-lighting-engine PRs remain untouched.
