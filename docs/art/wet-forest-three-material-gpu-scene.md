# Wet Forest — reuse our original material artwork in the real GPU scene

**Status: draft visual review, not production art approval or live Hunt adoption.**

## Corrected source-of-truth decision

The three new 256px flat-color materials were rejected for not matching WyrmForge.
They are no longer used or generated by PR #361. Do NOT replace them with new
procedural artwork or silently regenerate art outside the existing workstreams.

**The only ground artwork for this integration comes from:**
- Original Wet Forest 6×6 source-archive PR #340, source files under
  `user_handover_files/concepts/arena-v2/wet-forest/ground-materials/v1/`.
  The 18 original Grass/Moss, Trampled Earth and Wet Mud WebPs, plus the
  source manifest, were copied into PR #361 as **the exact original Git blobs**.
- PR #340's original `build_grass_moss_art_candidates.py`,
  `build_wet_mud_art_candidates.py` and
  `build_trampled_earth_art_candidates.py` plus their original dependencies.
  They produce six **already-designed, source-backed** 900px candidates per
  family, not a new material aesthetic. Archive sources remain immutable.
- The existing in-game six-swatch painted atlas stays available as an A/B
  comparison and is not changed or replaced in production Hunts.

The PNG candidates remain explicitly **unapproved** and have baked artist
highlights. Their pixel edge parity is not a guarantee of pleasing tiling,
light-neutral albedo, nor coherent path motif direction. **The user approves
artwork**; CI only verifies export integrity and renderer behavior.

## One seeded scene, no separate terrain or renderer

The `/arena-material-kit?seed=1204` page asks C#
`HuntArenaGenerator.GenerateWetForest(seed)` for the authoritative path,
ground regions and site. JS classifies the existing C# recipe into three
material surfaces. It never paints an independent road or infers water from
dark RGB. The selected archived artwork is sampled continuously in world
coordinates, not restamped from scratch per 16px world cell.

The scene is lit by the **existing** shared GPU `lighting/engine.js`; it
also consumes the existing provisional green-channel roughness map without
claiming it is an approved material. Light sources OFF means world RGB black.
There is no production Hunt, collision, player, water, or lighting refactor.

## Build locally

Install `tools/art/painted-requirements.txt`, then run from the repository
root:

```bash
output=src/Wyrmforge.Presentation.Web/wwwroot/art/environment/wet-forest-source-backed/v1
python3 tools/art/build_grass_moss_art_candidates.py --output "$output/grass-moss-art-candidates"
python3 tools/art/build_wet_mud_art_candidates.py --output "$output/wet-mud-art-candidates"
python3 tools/art/build_trampled_earth_art_candidates.py --output "$output/trampled-earth-art-candidates"
```

These are the copied PR #340 source-art exporters. They preserve the
original paintings and their source hashes and do not alter runtime gameplay.
All relevant CI workflows invoke them before preview app packaging.

## Original-source material contact refinement (26 October 2026)

**Problem observed in actual Chromium/390px neutral-light GPU screenshots:** Grass/Moss and Trampled Earth retained their desired detailed painting style, but their contact followed hard 16px terrain cell boundaries and made obvious squared-off edges. Replacing those paintings again would be the wrong fix.

**Changes limited to the review compositor:**
- `sourceBackedBoundaryContacts` traverses only existing C# material-cell boundaries and computes continuous, deterministic 2px-high / 2px-wide contact ribbons with maximum 5px displacement. Each contact copies pixels **directly from the same original PR #340 material**; no RGB crossfade, drawing new leaf patterns, procedural material generation or alpha-keyed black backgrounds.
- The material board, C# path, site, puddle classification, and provisional roughness texture are identical in both modes. The old stepped boundary stays selectable as `Previous stepped contacts` for same-seed, same-light A/B comparisons.
- Browser acceptance automatically captures original/organic boundary modes at 320px and 390px. Tests assert different framebuffer hashes, exact restoration when switched back, unchanged source identifiers, deterministic contact lists and no invented material IDs.

**Scope/approval:** this is only a **visual boundary treatment for archived artwork**, not a new road engine, redesigned texture bank or neutral physically separated albedo. Visual review remains necessary, especially crossing/corners, width of contact regions and night legibility. Source WebPs and PR #340 exporter code are unchanged.
