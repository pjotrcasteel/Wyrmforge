# Shared sprite animation layers — implementation checkpoint

The owner authorized a reusable locomotion/action compositor using existing sprites, after observing the Hollow sliding during a planted-foot attack. No additional color sprites or animation poses are authorized or needed for this slice.

The planned shared controller keeps locomotion phase driven by displacement independently of action time, uses named body regions and attachment points from a creature profile, and preserves full-body actions for body-plan-specific moves. Death overrides active layers; freeze/pause suspend phase. C# remains authoritative for damage and movement. Direction changes carry gait phase.

For the first proof, the Hollow's original Blender rigs provide semantic skin ownership and per-frame pelvis attachments. The existing 96px walk and 128px attack PNGs are sampled into a common 128px compositing space without changing their pixel density. Metadata contains clipping runs and landmarks, not color artwork. A moving attack combines walking support regions with the attacking action region, aligned at the pelvis. Stationary attacks retain the approved complete pose.

The Hollow implementation passes local controller, metadata, native-pixel compositor and actual-combat browser gates. The owner accepted the directional follow-up and authorized shipping version 0.0.135 through [PR #165](https://github.com/pjotrcasteel/Wyrmforge/pull/165). Final PR CI and Pages deployment are pending at this release checkpoint. Physical mobile performance and visual profiles for other enemies remain separate validation gates. Other enemies retain their existing presentation until their profiles are proved.

## Checkpoint: controller and native-pixel compositor

The shared modules and Hollow profile are implemented. Locomotion retains its distance phase beneath independently timed attacks. Profiles select named regions or a full-body action; optional authoritative action progress is supported. Unit cases cover a second, nonhumanoid profile, priorities, held death, freeze/pause, stationary attacks and phase carry. This proves profile independence, not a visually validated second enemy.

All 221 JavaScript tests pass, including metadata integrity and direction-follow regressions. Both actual-combat Hollow browser tests pass against the Release publish. The local Edge compositor review covers all eight directions and sixteen action frames: 49,734 unoccluded support pixels match the existing walking PNG exactly; 2,575 support pixels are legitimately covered by the translated action mask. An earlier screen-row comparison incorrectly counted hands/clothing as feet and was replaced with semantic support-region checking. All runtime color PNGs remain unchanged. The waist overlap and pelvis alignment look coherent in the eight-facing contact sheet and 390px actual-combat captures.

The cache reuses at most 96 native 128px canvases (6 MiB pixel storage). A desktop Edge benchmark of 96 simultaneously attacking actors over 90 frames measured median 1.3 ms / p95 3.4 ms for composition and drawing. This is not physical mobile hardware validation. The existing walk/contact/death capture also passes with the layered renderer, including held death frame 23. Its full transient report is `artifacts/sprite-layer-regression/browser-report.json`.

To reproduce actual combat evidence, publish the web project, serve its `wwwroot` with the existing SPA server, then run `node tools/sprite-lab/capture-sprite-layer-combat.cjs artifacts/sprite-layer-combat http://127.0.0.1:4184`. The committed `HollowBrowserTests` regression runs in normal Browser smoke CI. For visual comparison, Enemy Lab accepts `&blend=whole` to show the prior whole-body attack. This query applies only to the lab.

Each creature adapter owns simulation-to-presentation signals, not a separate playback algorithm. Call `updateSpriteAnimation` with displacement, delta time, movement/freeze/pause state, facing and an action `{name, token, progress?}`. Tokens identify one action occurrence; progress, when supplied, is authoritative and should be supplied throughout that occurrence. The shared result contains independent base/action clip frames and region names. Feed it to the compositor when `layered` is true; otherwise draw the selected original full-body clip. Handle death events before living-actor drawing, as the Hollow adapter already does.

Profiles describe locomotion clip/frame count/stride and each action's timing, priority, mode, support region and action region. A serpent may use `coils` plus `head`, a quadruped may use `body` plus `neck`, and a pounce or roll may explicitly use `fullBody`. No controller code assumes a pelvis, humanoid, eight facings or sixteen frames. Metadata supplies the actual per-frame attachment and clipping runs in a shared native-pixel coordinate space; it must match the source PNG hashes. Hollow frame 0/15 explicitly carries the current base pose across attack entry/exit; it does not reset walking phase.

Direction follow-up: removed the old adapter's attack-facing lock. During an action the Hollow now follows its target; the shared controller optionally turns through profile-provided direction rows at a configurable angular speed (Hollow 720 degrees/second, with boundary hysteresis). Both layers use the same current row and retain their independent phases. Freeze/pause hold the facing too. Pixel art uses discrete neighboring views rather than translucent overlapping silhouettes. Target-follow and shared turn progression unit tests pass. The updated actual-combat capture passes with four facings during the ongoing attack, and both Hollow browser regressions pass against the new Release publish. Current main was checked at 6f083e0e; the concurrent Refuge work is untouched.

Flattened sprites cannot reveal pixels hidden in the source pose. Therefore a new anatomy needs its own masks, attachment and occlusion review before enabling layering. Whole-body alpha crossfades are deliberately absent: they create doubled silhouettes in pixel art and do not restore walking feet. The current compositor draws walking support, then attacking action; an enemy needing interleaved front/back appendages needs additional ordered region support before rollout. The generic playback tests cover a nonhumanoid profile, but do not claim another monster's art is visually validated.

Research principles: [Unity masked animation layers](https://docs.unity3d.com/6000.0/Documentation/Manual/AnimationLayers.html) and [Spine animation tracks](https://esotericsoftware.com/spine-applying-animations) establish independent locomotion/action layering for skeletal data. Our implementation adapts the layering principle to existing sprite pixels rather than claiming skeletal interpolation of PNGs. [Godot discrete carry](https://docs.godotengine.org/en/stable/tutorials/animation/animation_tree.html#blendspace2d-and-blendspace1d) supports retaining playback phase for frame-by-frame art. [Canvas clipping](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/clip) provides the browser compositing mechanism. None of these sources guarantees seam-free composition of arbitrary flattened poses; that is a visual gate for this implementation.
