# Original 32×32 Wet Forest prototype — AR4 source study (30 October 2026)

**Status: source-authored visual candidate; not approved; not connected to live Hunts.**
The canonical AR0–AR7 milestone/approval contract is [the roadmap](../canon/roadmap.md#world-authored-arenas-and-groundmaterial-fidelity--ar0ar7-owner-decision-29-october-2026-locked). This document is an implementation record, not a replacement architecture.

## Intent and rights

Seven downloadable example packs were supplied as visual references to learn techniques: clean 32×32 pixel clustering, tile variation, organic edge treatments, small silhouettes, layered vegetation and readable material vocabulary. **Do not import, trace, recolor, or repackage any pixels, animations or textures from those packs.** They are not game dependencies. Pack terms vary even when files are described as free; preserve each original license for future reference, and do not submit third-party reference artwork to AI image tools where prohibited. This implementation generates its pixels from independent authored JavaScript primitives and color palettes.

Gothic Diablo-like atmosphere and grounded 2.5D presentation remain locked. Dark forest floor and muted highlights are intentional; magic illumination belongs to the existing G0–G5 shared GPU renderer.

## First checkpoint: WF32-P0

The opt-in source module is `tools/art/prototypes/wet-forest-32.mjs`, built on the repository's existing `Bitmap`, `rng`, `packAtlas` and PNG encoder. The first checkpoint produced 16 original frames; the **WF32-P1 technical revision now produces 22 native 32×32 frames:**

- Three variants each: forest soil, wet grass, mud and weathered stone (12 total).
- Pixel-stepped edge studies for grass/mud, grass/soil, soil/mud, soil/stone in vertical and horizontal orientations (8). These are **art-only** demonstrations, not approved production blending logic; AR3 weight maps remain authoritative.
- Transparent grounded details: root and fern (2).

The module imports without changing the game. It creates PNGs only when run as a command:

```sh
node tools/art/prototypes/wet-forest-32.mjs
node --test tests/javascript/wet-forest-32.test.mjs
```

Default generated output: `docs/art/previews/wet-forest-32/atlas.png`, `contact-4x.png`, `composition-study.png` and `manifest.json`. The manifest contains per-frame atlas source rectangles, anchor positions, deterministic ordering, pixel dimensions, and original-art provenance. Artifacts generated by this standalone review CLI are **not** included in the normal live `build-art.mjs --check` output and need not change existing versioned runtime atlases. Review images represent **source art, not actual gameplay screenshots**.

## WF32-P1d — generic terrain grammar (30 October 2026)

**Developer checkpoint only; art and AR4 gameplay adoption remain unapproved.** The four material transition studies are opt-in source images, not a playable Hunt screenshot.

### Implementation and ownership

- Source: `tools/art/prototypes/terrain-material-grammar.mjs`; `tools/art/prototypes/wet-forest-masonry.mjs`; `tools/art/prototypes/build-terrain-grammar-review.mjs`. The already authored `wet-forest-32.mjs` prototype is preserved.
- Material definitions: grass, soil, mud (soft) and flagstone, cobble, brick (hard). Every new material declares kind, relief and roughness/specular hints, plus allowed microdetail types. Material names are visual descriptions; C# still owns map/geography and gameplay meaning.
- Generic boundary policies: soft↔soft uses organic pixel-cluster mixing; hard↔soft removes **entire connected stone faces** intersecting soft material, retaining continuous masonry elsewhere; hard↔hard uses a structural junction with missing faces revealing underlying soil. Direction masks cover four edges and outer corners; arbitrary per-tile flipping is forbidden.
- The art painter generates one coherent 256px world field before cutting 32px cells. The 256px period is an authoring phase; a later runtime adapter must avoid stamping the same period across the entire world.
- Small mushrooms, pebbles, dead leaves, twigs, moss and roots are reusable overlays with per-material compatibility and deterministic world placement rather than duplicates inside every base tile.
- The existing shared G engine contract is `LitMaterial.albedo`, `normal`, `roughnessMap`, and **scalar** `specular`. Current G does *not* accept `specularMap`. Produce normal and roughness textures and a separate non-runtime specular reference guide. Roughness is non-color data in green channel. No new shader or lighting engine is introduced.
- Generator: `node tools/art/prototypes/build-terrain-grammar-review.mjs docs/art/previews/wet-forest-grammar-v1`. Outputs four review sample material bundles, PNG map triplets, extra specular guides, and a manifest that explicitly marks all approvals false. No generated images are loaded by live Hunts.
- Verification: 11 local Node test groups pass across the P1c masonry and P1d generic suites, including whole-stone deletion, 32px exact map reconstruction and deterministic exports. Full repo CI and real mobile screenshot/performance acceptance are separate gates.

### Next acceptance gates

2. AR3 C# geographic/site/material-weight owner approval before any production material cutover.

## WF32-P1e — terrain grammar v1.1 and art-quality response (30 October 2026)

**Still a source-only art candidate.** Owner feedback remains binding: stone joins should not read as perfect dark lines; paving must appear physically eroded and grass/mud must not look flat. Nothing here constitutes owner visual approval or in-Hunt lighting acceptance.

### Generic system commitments

- Four reusable classes: **soft organic**, **hard placed**, **loose scatter** (detail), and **wet reflective** (modifier). The last two never become independent C# terrain authority by adding a cosmetic overlay.
- Tile roles: fill, optional four cardinal edges, optional outer/inner corners, broken edges and transition fillers; do **not** require every material to export every possible permutation. A world-space boundary mask maps into the necessary roles.
- Generic boundary policies remain soft↔soft mingle; hard↔soft whole-stone removal with soil/moss infill; hard↔hard structural transition. A soft blend no longer assumes its edge is vertical. Directional masks support four edges and outer corners; inner-corner fit and world-wide repetition are pending.
- Microdetail compatibility includes pebbles, mushrooms, fallen leaves, twigs, roots and moss. Wetness overlay changes non-color G-channel roughness and preserves albedo/normal/identity, without a new GPU shader or fake specular texture binding.
- Lighting output remains albedo (sRGB), normal (linear), roughnessMap (linear/G channel) and scalar specular. The specular-guide PNG is an art reference **only**; the real LitMaterial does not accept a specularMap.

### Concrete art quality changes

- **Hard surfaces:** weakened contrast in joints; more fully absent, broken and sunken stone faces; dark mortar filled with warm packed earth or moss rather than outlining every slab.
- **Grass:** periodic multi-scale clusters, uneven tuft density and exposed soil pockets; no tile-local reset.
- **Mud:** broad tone variation and curved packed channels, retaining lighting-neutral albedo; damping can be layered as roughness, not a prepainted glint.
- **Review:** opt-in `build-terrain-grammar-review.mjs` still exports 4 example compositions, native normal/roughness and specular guide sheets; additionally exports `mud-damp-roughness.png` and versioned grammar metadata.
- **Regression checks:** 15 local Node test groups passed (11 existing + 4 new in `terrain-material-grammar-v1-1.test.mjs`). GitHub CI is independent and should be checked before merge.

### Known limitations / next gate

A 256px authored sample period remains visually repetitive when stamped over a large playable map. This material grammar does not infer road location or terrain state from artwork: AR3 C# site material-weight fields must drive real-world selection and dynamic boundaries. More complex structural transitions, inner corners, ecological prop placement, physically authored relief maps, shared G live texture registration and real-device profiling remain open. WF32-P1e does **not** pass owner aesthetic acceptance, AR3 acceptance or AR4 integration.

## WF32-P1f — line-language refinement (30 October 2026)

**Scope:** respond specifically to owner criticism of overly continuous, hand-drawn contour lines in the flagstone/cobble material studies. The broader material/boundary grammar and approved art direction remain unchanged. This is an opt-in source-only candidate; owner visual sign-off remains open.

### Why the previous approach failed

The original Voronoi/stone illustrator used a dark outline for almost every stone, and the edge-erosion pass inferred individual stones by flood-filling pixels selected by their exact visible colors. This meant making the stonework less outlined could merge several stone identities and break whole-stone deletion. The correct fix was **not** to preserve drawn ink for physics: it was to decouple authored stone topology from the displayed surface.

### Implementation

- `createMasonrySurface(type,seed)` returns `{bitmap,stoneIds}` for original flagstone and cobble patterns; `createMasonryField` preserves the historical bitmap-only API for atlas tools. Each nonmissing stone has a stable ID even if its visible joint is fully suppressed.
- `classifyStoneInstances(bitmap,stoneIds)` now accepts explicit IDs where provided (the previous visible-pixel flood fill is retained for legacy/brick source). Whole-stone erosion and structural hard/hard transitions use that topology and keep arrays sized to the maximum ID, not the number of nonempty stones.
- Thin, complete Voronoi contour strokes are replaced with **interrupted, low-contrast** soil/moss joins, a narrower shaded chip band, and localized stone patina clusters. Faces are shaded in a restricted dark range, keeping normal dark-fantasy legibility without outlining every polygon.
- Soft organic palette transitions now use deterministic 3px threshold clusters, avoiding the artificially closed color contours produced by broad quantization. The painter still authors a coherent 256px phase field before cutting 32px cells.
- The shared G engine's `albedo`, `normal`, `roughnessMap` + scalar `specular` contract is unchanged. No runtime lighting or C# gameplay integration was made.

### Checks and acceptance

- The source and preview generator still run with:
  `node tools/art/prototypes/build-terrain-grammar-review.mjs <output-directory>`.
- Previous Node test suites remain active; `terrain-material-grammar-line-language.test.mjs` adds five test cases verifying stability under arbitrary recoloring, continued whole-stone removal on two boundary orientations, and exact 32px reconstruction of the G-compatible maps.
- **20/20 local tests pass**. Source-art before/after review is available; GitHub CI and real-Hunt mobile verification are separate.
- Visual approval is **not** assumed. The remaining art question is whether subtle edge implication, surface weathering and color differencing strike the right balance versus the now-weaker outlines.

### Follow-up

WF32-P1g will address world-scale repetition across 256px patches, inner corners, additional material pairings and ecologically authored detail placement **after** owner P1f art review. Production GPU material-adapter integration remains gated by approved AR3 geography and its shared G renderer.

## WF32-P1g — line-free organic texture and subtle stone patina (30 October 2026)

**User feedback:** the lower half of the P1f image was preferred, but the grass and soil still contained graphic contour lines and the stone faced looked flat. The approved material/boundary grammar and stone shapes are preserved. This is a source-art iteration, not approval of visuals or gameplay.

### What changed

- Soft ground no longer quantizes smooth noise into discrete color bands, which previously created long artificial isolines. Instead, a continuous blend between existing muted palette values is textured with native 2–4px contiguous pixel clusters and short surface details. The broad shade fields remain deterministic at world phase, independent of 32px atlas cells.
- Grass: short grouped blades and sparse exposed earth pockets; no long continuous stems or traced patch boundaries. Forest soil: compact granules and organic clods instead of long scratch strokes. Mud: shallow short depressions and crushed grit instead of long random channels (traversal ruts remain future **C# AR3** site geography).
- Flagstone/cobble receive very subtle clustered face patina and small tonal variation, without returning to the rejected dark, complete contours.
- **Material maps** (albedo in sRGB, normal and roughness non-color) are still generated through the same shared G material contract; no new renderer or alpha/lighting tricks.

### Technical checkpoint / validation
